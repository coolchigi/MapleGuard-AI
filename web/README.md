# MapleGuard — live dashboard

The proof surface. Two editorial "passport" panels rendered from the **real**
deterministic CRS engine:

- **Position** — today's CRS (496/1200), the cited "how this number is built"
  breakdown with IRCC category caps, and the COMPUTED · NOT ADJUDICATED stamp.
- **Time machine** — an interactive scrubber you drag across dates. The CRS
  number falls at each real cliff: **496 → 491 → 342** (language-test expiry,
  −149) → 336 → 331 → **325**. Every value comes from the engine, none are typed by hand.

Interactive: the time-machine scrubber (drag with mouse/touch, or focus the
handle and use ← → / Shift+← → / Home / End). The hero number, the dot on the
step line, the delta-from-today readout, and the highlighted cliff row all track
the scrubbed date live.

## Where the numbers come from

`src/data/demo.json` is generated by running the actual `crs` engine once:

```bash
npm run precompute          # cd .. && PYTHONPATH=. python3 web/scripts/precompute.py
```

The app never computes a CRS number, it renders these. Re-run after any engine
change. See `scripts/precompute.py` for the demo profile (the shape in
`tests/test_timeline.py`).

## Run locally

```bash
npm install
npm run dev                 # http://localhost:3000
```

## Deploy to Vercel

Standard Next.js App Router, no exotic config. The page is fully static.

1. `npm i -g vercel` (once), then from this `web/` folder: `vercel`
2. Set the Vercel project **Root Directory** to `web` (the repo root is the
   Python engine, not the app).
3. `vercel --prod` to promote. No env vars needed.
